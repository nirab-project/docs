## 1. النطاق الثابت في المراحل الثلاث

### داخل النطاق

لوحة الإدارة المركزية وصفحاتها داخل جميع موديولات الباك إند، قوالبها المشتركة، صفحات الدخول التابعة للإدارة، وقوالب العرض المستقلة مثل الفواتير والطباعة من ناحية المظهر فقط.

العمل يبدأ من المصدر المحلي الحالي المعتمد على `main`. مسارات الخطة السابقة نقاط بداية للجرد وليست دليلًا على أن نسختها هي آخر نسخة محلية. افحص حالة العمل الحالية ولا تحذف أو تتراجع عن تعديلات المستخدم.

تطبيقات Flutter وموقع العميل وإعادة تصميم كامل لوحة الفرع خارج النطاق. راجع فقط أثر الأصول والقوالب المشتركة عليها كي لا يتسرب التصميم إلى واجهات غير مستهدفة.

### المسموح

- تعديل قوالب Blade من ناحية بنية العرض وتنظيم المحتوى فقط، دون تغيير الشروط الوظيفية أو شروط الصلاحيات.
- إضافة أو تعديل CSS الخاص بالهوية، وتحميل الخط المحلي الحالي، وأصول الشعار المعتمدة.
- تحسين JavaScript الخاص بالتفاعل البصري فقط: فتح الأقسام، التبويبات، ترتيب التركيز، رسم البيانات الحالية وتنسيق عرضها.
- إضافة مكونات عرض مشتركة وإعادة استخدامها، مع الحفاظ على عقود الصفحات الحالية.
- تعديل النصوص المرئية عبر نظام الترجمة القائم دون تغيير مفاتيح داخلية أو قيم مخزنة أو رموز حالات.

### الممنوع

- تغيير Controllers أو Services أو Models أو Repositories أو Requests أو Routes أو Middleware أو Policies أو Gates أو Jobs أو Events أو listeners أو الاستعلامات أو APIs.
- تغيير مخطط قاعدة البيانات أو تنفيذ migrations أو seeders أو أي اتصال بقاعدة البيانات لأغراض هذه المهمة. يظل MySQL 8 + Spatial كما هو.
- تغيير التسعير أو الضرائب أو الخصومات أو العمولة أو التحصيل أو الدفع أو الاسترداد أو العهد أو الضمان أو الباقات أو الجدولة أو الإسناد أو انتقال الحالات.
- تغيير الصلاحيات ونطاقات الفروع أو تحويل ملفات خاصة إلى روابط عامة.
- تغيير endpoint أو HTTP method أو request payload أو أسماء الحقول أو قواعد التحقق أو سياسة retries أو معالجة حالة الأعمال.
- تغيير إعدادات البيئة أو التهيئة التشغيلية أو feature flags أو ملفات الأسرار أو النشر.
- ترقية أو استبدال Bootstrap أو jQuery أو أي مكتبة، أو تعديل vendor، أو إنشاء تطبيق واجهة جديد.
- إصلاح عطل منطقي قديم مصادفةً أثناء إعادة التصميم. وثّقه خارج النطاق ولا توسّع المهمة من تلقاء نفسك.

**تنبيه:** وجود كود داخل Blade أو JavaScript لا يجعله تلقائيًا كود عرض. الحسابات والتحقق والصلاحيات وتحويلات البيانات وطلبات الشبكة في هذه الملفات محمية أيضًا.

## 2. قواعد الحفاظ على الوظائف

احفظ كما هي روابط المسارات، `form action`، `method`، `enctype`، حقول CSRF وmethod spoofing، وأسماء الحقول وقيمها المخفية. لا تنقل حقلًا خارج النموذج الذي يجب أن يرسله، ولا تنشئ نماذج متداخلة.

احفظ `id` و`data-*` والمحددات التي تعتمد عليها الأحداث والطلبات الحالية. استخدم أصنافًا إضافية للتصميم بدل إعادة تسمية hooks الوظيفية. عند الحاجة إلى ترتيب DOM، راجع ارتباط الأحداث وعدم تكرار ربطها أو اختفاء عناصر يحتاجها الكود.

احفظ شروط `@can` و`@canany` ونطاقات الوصول والحالات التي تسمح بالأزرار أو تمنعها. إخفاء العنصر ليس بديلًا عن الصلاحية، والتصميم الجديد لا يمنح وصولًا جديدًا.

تغيير تنسيق رقم أو تاريخ في النص المرئي لا يغيّر قيمته الخام أو توقيته أو وحدته أو صيغة إرساله للخادم. لا تُنشأ حسابات مالية جديدة في المتصفح.

## 3. الفحوص المسموح بها في كل مرحلة

الفحوص خفيفة وساكنة، ولا تحتاج تشغيل التطبيق أو بياناته:

- مراجعة `git diff` وأسماء الملفات المتغيرة مقابل نطاق المرحلة، وفحص `git diff --check`.
- قراءة القوالب للتأكد من بقاء شروط الصلاحيات وحقول النماذج والمحددات والمسارات والحمولات الأصلية.
- فحص صياغة JavaScript بأداة محلية موجودة ومناسبة لنوع الملف، دون تثبيت أدوات أو تشغيل scripts المشروع.
- فحص PHP الخالص بـ `php -l` عند وجود مقتطفات PHP خالصة تستدعي ذلك؛ لا يُعد هذا تحققًا من صحة توجيهات Blade أو عمل الصفحة.
- مراجعة مراجع الخط والشعار وملفات CSS/JS محليًا، والتحقق من وجود المسارات دون طلبها من خادم الإنتاج.
- استخدام أداة lint محلية موجودة فقط إذا كانت محدودة على الملفات المعدلة ولا تشغّل التطبيق ولا سلسلة مهام واسعة. عند غيابها يُذكر أنها غير منفذة.

لا تشغيل Laravel أو Docker أو خادم محلي، ولا `artisan` أو اختبارات PHPUnit/Pest أو Playwright/Cypress أو E2E أو Lighthouse أو لقطات شاشة أو rendering بصري. لا `composer install` أو `npm install` أو تنزيل تبعيات أو خطوط أو build شامل. لا اتصال بالإنتاج ولا إرسال عمليات أو نشر.

عند تعذر أداة فحص محلية، سجّل السبب ولا تثبت البيئة لتجاوز القيد. لا تعلن نجاح فحص لم تنفذه.

## 4. المرحلة الثالثة — تعميم بقية اللوحة والإغلاق المصدري

### الهدف

تغطية بقية صفحات الإدارة فعليًا وإزالة التفاوت المتبقي، ثم تسليم مصادر منظمة جاهزة لمراجعة صاحب المشروع. هذه مرحلة تنفيذ تصميم كبيرة، وليست مرحلة اختبارات بصرية.

### المطلوب

1. **التعميم:** راجع صفحات الفروع والعملاء والخدمات والتصنيفات والتقارير والمالية والعهد والتسويق والمحتوى والموظفين والإعدادات والتكاملات وغيرها مما يوجد فعلًا في جرد الإدارة.
2. **كل الموديولات:** لا تقتصر على `AdminModule`؛ اتبع القوالب الإدارية داخل الموديولات الأخرى. لا يُعد وراثة قالب جديد دليلًا وحده على اكتمال محتوى صفحة لها CSS/JS مستقل.
3. **الشاشات المستقلة:** وحّد مظهر الفواتير والطباعة وصفحات الأخطاء والمصادقة التابعة للإدارة بحسب وجودها، دون تغيير توليد المستندات أو محتواها المالي أو محركها. لا تولّد PDF أو صورًا للتحقق خلال عمل الوكيل.
4. **الخط الكامل:** تتبّع الاستثناءات الباقية في العناوين والحقول والقوائم والرسائل والمحررات والرسوم والطباعة، مع الحفاظ على الأيقونات ودعم الأرقام والمراجع.
5. **الأنماط المتعارضة:** قلّل التكرار والتجاوزات في CSS الخاص بالمشروع فقط، ولا تحذف تنسيقًا مشتركًا دون تتبع مستخدميه. لا تجعل التنظيف إعادة هيكلة عامة للمنطق.
6. **الحالات التفاعلية:** أكمل مظهر التركيز والتعطيل والتحويم والتحميل والنجاح والخطأ وعدم وجود البيانات باستخدام الحالة التي يقدّمها التدفق الحالي. لا تنشئ نظام معالجة طلبات بديلًا.
7. **RTL والمقاسات والمظهر المحفوظ:** راجع الكود المسؤول عنها ساكنًا وأكمل تعريفاتها. اترك التحقق الفعلي على الشاشات والتكبير لصاحب المشروع.
8. **المراجعة النهائية:** راجع فروق جميع المراحل مقابل خط الأساس المسجل، واحصر الملفات الخارجة عن النطاق وأي تعارضات غير محسومة. استخدم الفحوص الخفيفة فقط.
9. **التغطية:** لكل صفحة حالة واضحة: منفذة مصدريًا، متأثرة بالأساس فقط وتحتاج عملًا، مؤجلة بسبب قيد، أو خارج النطاق. لا تُخفى فجوات التغطية وراء عبارة «شملنا كل اللوحة».
10. **تسليم الاختبار:** أعد قائمة موجزة بصفحات ومسارات وتفاعلات تحتاج مراجعة صاحب المشروع؛ لا تنفذ المراجعة ولا تنتج صورًا أو تقرير نجاح بصري.

### التسليم النهائي

مخرجات توثيق مقترحة ينشئها الوكيل داخل موضع التوثيق المعتمد في المستودع:

```text

NIRAB_ADMIN_UI_PHASE_02_REPORT.md
NIRAB_ADMIN_UI_PHASE_03_REPORT.md
NIRAB_ADMIN_UI_COVERAGE.md

```

يسجل كل تقرير: ما نُفذ، الملفات المتغيرة، الفحوص المنفذة فعلًا ونتائجها، ما لم يُفحص، وما تعذر ضمن الحدود. لا يرفع أسرارًا أو بيانات عملاء أو ملفات خطوط إلى التقارير.
