# NIRAB V2 — حزمة تنفيذ إعادة الهيكلة الشاملة
**الإصدار:** 1.0 — 13 نوفمبر 2026  
**نوع التسليم:** مواصفات وأوامر عمل للوكيل، وليست برنامجاً منفذاً أو إذناً بالنشر.  
**المنتج:** NIRAB Clean — شركة واحدة، مدن معتمدة، فرع واحد حصري لكل مدينة، دون سوق مزودين أو عمولات.

## القرار الملزم
أعد بناء نواة الخدمات والتجارة والسلة والجدولة والتشغيل عند الحاجة، دون إلزام بالتوافق مع البيانات التجارية التجريبية السابقة. يسمح المالك بتصفير الخدمات والعملاء التجريبيين والحجوزات والمبيعات والأرصدة التجريبية والتقارير التابعة لها. **لا يسمح بحذف أو تغيير التهيئة والمفاتيح والتكاملات والمدن وحدودها والفروع والحسابات الداخلية اللازمة لها.** التصفير ليس جزءاً من migration عادية ولا من startup.

### ثلاث حدود تنفيذ منفصلة
| المسار | ما ينفذه الوكيل | ما لا ينفذه |
|---|---|---|
| PH-00 إلى PH-11 | قراءة المصادر، تعديل الكود، كتابة migrations وseeders والاختبارات والتوثيق، مراجعة ثابتة | لا بيئة تشغيل، لا Docker up، لا قواعد بيانات، لا seed/migrate، لا اختبارات أو builds أو تثبيت اعتمادات |
| PH-12 — مرحلة نهائية مستقلة | إنشاء بيئة محلية معزولة بالكامل، تثبيت الاعتمادات، Docker، MySQL، تشغيل كل الاختبارات والبناء والواجهات | لا اتصال بالإنتاج، لا مفاتيح حقيقية، لا نشر، لا ترحيل VPS |
| OWNER-ONLY | المالك ينفذ لاحقاً التحويل والنسخ والتصفير والترحيل على VPS يدوياً | الوكيل لا يدخل VPS ولا ينفذ هذه الأوامر نيابة عن المالك |

**الانتقال إلى PH-12 مسموح ضمن هذا التكليف بعد إكمال بوابة CODE-READY لجميع المراحل البرمجية. لا يلزم انتظار إذن جديد لتجربة محلية آمنة. بوابة VPS غير مأذون للوكيل باجتيازها إطلاقاً.**

## ابدأ بهذا الترتيب
1. اقرأ [أمر الوكيل](01-AGENT-EXECUTION-CONTRACT.md) و[تدقيق المصادر](02-SOURCE-AUDIT.md).
2. اقرأ [القرارات الملزمة](03-DECISIONS-AND-SCOPE.md) وجميع مواصفات `specs/` والعقود `contracts/`.
3. نفّذ الملفات `phases/PH-00...PH-11` بالترتيب. دوّن التقدم في `templates/EXECUTION-STATE.json` بعد نسخه إلى مجلد تقارير التنفيذ في المستودع.
4. بعد اكتمال الكود، نفّذ [PH-12](local-validation/PH-12-LOCAL-FULL-VALIDATION.md) وحدها، وأصلح الأخطاء التي تكشفها الاختبارات ثم أعد الاختبارات المتأثرة واختبارات الانحدار.
5. سلّم تقارير التنفيذ وحزمة التحويل المقترحة ونتائج الاختبارات. يستخدم المالك [قائمة القبول اليدوي](acceptance/01-MANUAL-ACCEPTANCE.md)، ثم [دليل VPS](owner-only/01-VPS-CUTOVER-RUNBOOK.md) لاحقاً.

## المقصود بـ«كامل»
لا يكفي إظهار شاشات أو إنشاء جداول. يجب تنفيذ الإدخال والإدارة والتسعير والشراء والجدولة والتنفيذ والإلغاء والاسترداد والتقارير والتدقيق مع اختبارات موثقة. يوضح [جدول التتبع](04-REQUIREMENTS-TRACEABILITY.md) أين تنفذ كل متطلبات النطاق وكيف تقبل.

لا نطارد تطابقاً مع Clean Life ولا ننسخ كوده أو أصوله أو بيانات عملائه. التتبع السابق دليل على أنماط استخدام فقط؛ القرارات الجديدة في هذه الحزمة **تصميم مقترح لنيراب** وليست ادعاءات عن بنيتهم الداخلية.

## الحقيقة الحالية
هذه الحزمة لم تشغّل المشروع ولم تختبره ولم تمس بياناته. الأوامر الجديدة مثل `nirab:commerce-reset` وواجهات `/api/v2/commerce` **أسماء مطلوبة للتنفيذ وليست موجودة بالضرورة الآن**. لا تشغّل أي مثال VPS قبل أن يثبت تقرير الوكيل أنه نُفّذ واختُبر محلياً.
