# NIRAB Clean V2 — حزمة الوثائق التنفيذية النهائية للوكيل

> **اقرأ `00-START-HERE.md` أولاً ثم `01-AGENT-EXECUTION-CONTRACT.md`.**

هذه حزمة تكليف هندسي مستندة إلى أربعة أرشيفات مصادر NIRAB Clean المرفوعة (Backend, Customer, Provider, Serviceman) وتحليل تدفقات الخدمات والتسعير والسلة والجدولة. ليست شيفرة تنفيذية مكتملة أو تقرير نجاح اختبارات؛ على الوكيل تطبيقها والتحقق منها. السجلات والأمثلة المرجعية للتصميم فقط، وليست بيانات أو أسعار المنافس لإعادة استخدامها.

## أهم خمس قواعد ملزمة

1. **المشروع قبل الإطلاق التجاري.** يسمح بإعادة بناء نواة الخدمات والمبيعات والحجوزات وإعادة تهيئة بيانات التشغيل التجريبية؛ لا نحتاج الحفاظ على التوافق التجاري السابق.
2. **لا تمس التهيئة المحمية.** إعدادات النظام وأسرار الربط وFirebase والدفع وOdoo والبريد والخرائط والمدن وحدودها والفروع وعلاقات المستخدمين التشغيليين اللازمة لها تبقى، مع حفظ الصلاحيات اللازمة. حتى لو طلب لاحقاً تصفير العملاء، لا يمس ذلك حساب الإدارة أو مالك الفرع. يجب جرد التبعيات قبل أي حذف.
3. **PH-00 إلى PH-11: تعديلات كود وكتابة اختبارات فقط.** لا تشغيل Docker/DB/ويب/تطبيقات، لا تنزيل اعتمادات ولا migration/seed ولا دفع أو اتصال خارجي. يمكن فحص المصدر ثابتاً؛ تسجل الاختبارات غير المنفذة بوضوح.
4. **PH-12 وحدها: البيئة المحلية والاختبارات الكاملة.** يسمح بتشغيل Docker/MySQL/Flutter Web وBackend/لوحات الإدارة، واختبارات/بناء Android إذا توفرت الأدوات؛ بيانات صناعية وموصلات زائفة ولا اتصال ببيئة الإنتاج.
5. **ترحيل وتصفير بيانات VPS للمالك فقط.** يكتب الوكيل migrations وseeders وأوامر dry-run/apply آمنة ودليل إجراءات، لكنه لا ينفذها على VPS ولا يرفع تغييرات إلى فرع Git يمكن أن ينشر تلقائياً. نقوم بالتحويل اليدوي لاحقاً مع المالك بعد المراجعة والنسخ والتحقق.
