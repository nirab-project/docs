# S06 — عروض الأسعار والتنفيذ المتخصص
## عروض الأسعار والمعاينة
يختار العميل الخدمة/المتغير، ويستكمل النموذج والمرفقات والعناوين ثم submit صريح. حفظ draft أو فتح البطاقة لا يرسل Odoo ولا ينشئ عرضاً رسمياً أو حجزاً. guest قد يجهز draft؛ الإرسال النهائي يتطلب حساباً/جلسة هوية موثقة وفق auth الحالية، لا إنشاء هوية من الهاتف فقط.

الفرع يراجع ما يخصه وحده؛ يستطيع طلب معلومات، حجز inspection، أو إرسال quote version بمكونات وسعر/ضريبة/مدة وفريق وصلاحية وسياسات. معاينة مجانية مصرح بها تظهر «المعاينة مجانية؛ التنفيذ غير مسعر»، ولا تصف الخدمة كلها مجانية. معاينة برسوم fixed offer منفصلة؛ credit رسومها عند تنفيذ الخدمة يحتاج قاعدة dedupe واحد وذكرها في العرض.

العميل يقبل نسخة معينة غير منتهية ثم checkout يثبت الإتاحة والدفع. preferred date في quote ليست reservation. قبول quote دون إتمام checkout لا يعلن confirmed. رفض أو انتهاء العرض يحرر holds التابعة فقط، ولا يمس زيارات أخرى. الإدارة قد تعدل draft، لكن نسخة sent تُستبدل بنسخة جديدة؛ accepted لا تعدل.

## قوالب الخدمات المرجعية
### تنظيف الأثاث
اختيار قطع وكميات/قياسات أو باقة مركبة؛ نطاق كل جزء محفوظ. مثال كنب+سجاد+ستائر يخلق checklist واضحاً بكل الأجزاء. المساحة تدخل بوحدة m² لا «عدد أمتار» مبهم. يمكن إضافة خدمة منفردة للسلة دون إلزام شراء bundle.

### النظافة التأهيلية
property type، المساحة، عدادات أجزاء، instances أسئلة، مرفقات، خطة priced_by_form أو inspection. إذا تجاوزت الإجابات حدود التسعير الموثوقة تحول إلى quote مع السبب. لا جمع حد أدنى ورسوم معاينة وأصل الخدمة مرتين.

### المكيفات
single unit وquantity_bundle وإضافات فعلية مرتبطة بالباقة؛ small/large أو نوع الوحدة اختيار قابل للتكوين. أوقات الموارد تتغير حسب العدد. مدخل خدمة واحد في كتالوج نيراب، مع variants وليس نسخة «مستقلة» صفرية.

### الصيانة المنزلية
كهرباء/سباكة/تكييف كأقسام خيارات داخل الخدمة، وصف العطل ومرفقات وتشخيص. سياسة inspection fee واضحة. القطع والعمل الإضافي quote/amendment يقبله العميل؛ الفني لا يغير المبلغ/paid flag من شاشة عامة.

### مكافحة الحشرات
عقار ونطاق باقة single visit، درجات/نوع مشكلة إذا أعدها الأدمن. contract/visits لا يظهر enabled إلا إن كان قابلاً للشراء والجدولة؛ الضمان سياسة محتوى مع workflow follow-up، لا زيارة مدفوعة تلقائياً. safety conflicts config تتحقق قبل جمع مهام في المكان نفسه، ولا تُخترع تعليمات استعمال مبيدات داخل البرنامج.

### نقل الأثاث
متغير شقة/دور/فيلا، origin/destination addresses، الطوابق، مصعد، الوصول، قطع كبيرة، فك/تركيب، تغليف، مرفقات، preferred date. كلا العنوانين ضمن سياسة نفس المدينة في V2؛ غير ذلك طلب مراجعة غير قابل للدفع التلقائي. quote يحدد الفريق/السيارة كموارد إذا فُعلت. مناقشة المسافة لا تبرر اتصال Google حقيقي أثناء الاختبار.

### غسيل السيارات
brand → model dependent options؛ لون؛ لوحة؛ حجم/نوع السيارة إذا كان مؤثراً في تسعير نيراب؛ onsite location. اختيار أصل محفوظ أو إدخال جديد دون حفظ. brand/model validation server، تغيير brand يصفر model غير المتوافق. لا حاجة لتكامل Hamim. `vehicle size` إذا لا يؤثر في السعر لا نعرض فرقاً وهمياً.

### غسيل الملابس
offer capacity + wash count + preferences؛ اختر حفظ defaults أو تعديل لهذه الزيارة فقط. Organic/scent/mirzam/starch/protection خيارات من الأدمن؛ starch_level مشروط بـstarch=true، والخيارات المجانية لا تفرض رسماً. bag capacity التسويقية منفصلة عن measured_weight.
workflow: scheduled_pickup → picked_up (عدد الأكياس/دليل استلام) → received_at_branch → processing → quality_checked → ready_for_delivery → out_for_delivery → delivered. كل pickup/delivery له task وموارد وموعد؛ processing له checklist وليس بالضرورة حجز فني ميداني. order booking لا يكمل عند pickup. إثبات التسليم/OTP حسب policy؛ reuse OTP infrastructure دون تعطيل حماية الإنتاج. excess weight يولد adjustment، يقبل/يرفض بوضوح، مع طريقة معالجة النطاق الأصلي عند الرفض.

### سجاد المساجد
area m² + site access/conditions؛ ثابت محسوب إذا ضمن rules أو inspection. يعرض إجمالي واضح أو quote_required، لا 0 بدلاً من missing. نافذة الوصول مستقلة عن إجمالي العمل المطلوب. المساحة الكبيرة تزيد resource demand أو تحول للمراجعة، لا cap يخفض التكلفة اعتباطاً.

## تشغيل الفني والفريق
booking له tasks، والتعيين على الفنيين/فريق بموافقة المخول. task واحد لا يكلف فنيين بنفس الفاصل إلا كفريق مقصود. قائد الفريق يستطيع الإكمال فقط إذا checklist required/evidence/حضور الفريق تحقق حسب policy. فرع لا يرى bookings غيره؛ فني يرى assigned tasks فقط مع الحد الأدنى من بيانات العميل اللازمة للعمل.

الانتقالات en_route/arrived/start/complete تحمل version وidempotency key ووقت الخادم. client timestamps دليل إضافي لا مصدر المحاسبة. Offline UI يجوز queue أوامر محلياً مع UUID، لكنها تظهر pending sync، والخادم قد يرفض بسبب حالة تغيرت؛ لا يعرض paid/completed نهائياً دون إقرار خادم. GPS لا يصير شرطاً غير قابل للعمل إذا فشل الإذن إلا ضمن policy معلنة؛ لا تعطيل شامل لقيود الوصول.

## الإغلاق والنزاعات
شروط completion حسب الخدمة: جميع المهام المطلوبة + evidence + required confirmations. الدفع مستقل: يمكن completed/unpaid عند cash pending collection، وتظهر فاتورة مستحق لا paid. تقييم العميل وشكوى/إعادة عمل ترتبط بالbooking والservice snapshots. إعادة عمل warranty لا يحتسب إيراداً جديداً إلا قرار واضح، ويرث scope العمل لا يفتح تعديل سعر قديم.
