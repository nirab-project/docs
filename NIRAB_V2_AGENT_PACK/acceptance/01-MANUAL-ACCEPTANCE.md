# قائمة القبول اليدوي الجديدة لنيراب V2
هذه قائمة جديدة؛ لا تضاف نسبتها إلى قائمة اختبارات V1 القديمة. **كل الحالات الآن NOT_RUN** لأن هذه حزمة تكليف، وليست تقرير اختبار فعلي.

## طريقة الاستخدام
الوكيل يشغل ما يستطيع محلياً في PH12 ويسجل الأدلة. المالك يعيد فحص نقاط UI والتشغيل بعد التنفيذ، ثم يجري smoke آمنة على VPS بعد cutover. `LOCAL_ONLY` لا يجرى على الإنتاج مطلقاً، وخصوصاً التصفير والتزامن/العبث بالمدفوعات/تعطيل الحراس. `LOCAL_THEN_OWNER` يعاد على الإنتاج ببيانات المالك التجريبية المعتمدة فقط وبعد منع الاتصالات الخارجية غير المرغوبة.

المتطلبات السابقة: actors/scenarios من `fixtures/local-scenarios.json`؛ C-A/C-B عملاء اختبار، Manager-A/B فروع مختلفة، techA1/A2. استخدم تواريخ مستقبلية بالنسبة إلى clock الاختبار لا تواريخ نوفمبر في التتبع القديم. أسعار math fixtures ليست أسعار إنتاج. لا تغيّر clock الخادم؛ حقن الساعة محلياً فقط.

لكل حالة سجل PASS/FAIL/BLOCKED/NOT_RUN، رقم الإصدار، التاريخ، request_id/booking/order والسبب. أخفِ الأسرار والأسماء/أرقام الهواتف الحقيقية في الصور. P0/P1 فشل يمنع بوابة القبول؛ missing native/live evidence ليس PASS. screenshot وحدها لا تثبت ledger أو السعة: استعمل read-only audit report المرفق للوكيل.

**عدد الحالات المخططة: 119.**
