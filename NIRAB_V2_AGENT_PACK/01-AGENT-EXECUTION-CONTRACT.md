# أمر العمل الملزم للوكيل

أنت تنفذ إعادة هيكلة NIRAB Clean V2 في أربعة مصادر: Laravel Backend وFlutter Customer وFlutter Provider وFlutter Serviceman. اقرأ الحزمة كاملة، ثم نفذ المراحل بالترتيب دون الاكتفاء بخطة أو واجهات وهمية. الحزمة هي مواصفات هدف جديد؛ لا تفترض أن المسارات المقترحة موجودة حالياً.

## 1. الصلاحية والنطاق
- مسموح تعديل الكود جذرياً وإلغاء المسارات التجارية القديمة وتغيير عقود API والبيانات التجارية التجريبية. لا تبنِ طبقة توافق طويلة الأمد للعملاء القدماء؛ امنع النسخ القديمة من الكتابة عند التحويل.
- احتفظ بإطار Laravel وFlutter وMySQL وبنية الشركة الواحدة، وبنظام التهيئة والأسرار والخرائط والمدن والفروع. لا تحوّل المشروع إلى NestJS/React أو microservices أو سوق مزودين.
- لا تطبق اقتراحاً سابقاً بتعدد الفروع داخل المدينة: النموذج المعتمد **City → One Branch**. لا تختلق حدود مدن أو تعطّل حارس READ COMMITTED.
- احفظ الحسابات الداخلية المرتبطة بالفروع والفنيين والصلاحيات. الإذن بحذف «المستخدمين» يتعلق بالبيانات التشغيلية القابلة للتصفير؛ لا يكسر علاقات الفرع أو يحذف حساب المالك.
- نفذ النواة الجديدة بكل أطرافها، لا تنشئ جداول دون ربطها بالتطبيقات ولا endpoints غير مستعملة في الواجهة.

## 2. PH-00..PH-11 = CODE ONLY
اقرأ وعدل الملفات واكتب migrations/seeders/اختبارات/Compose/سكربتات التشغيل دون تنفيذها. يسمح بفحص نصي ومقارنة diff وبفورمات/فحص syntax لا يحمّل التطبيق إذا كانت الأدوات مثبتة أصلاً. يمنع خلال هذه المراحل:
`composer install/update`، `flutter pub get`، `npm install`، `docker build/up`، `artisan migrate/seed/serve/test`، PHPUnit، اختبارات Flutter، Playwright، builds، قواعد بيانات وخدمات محلية أو بعيدة.
كتابة الاختبارات تبدأ مع كل مكون؛ **تنفيذها مؤجل إلى PH-12**. لا تقل «ناجح بالاختبار» عندما تكون قد قرأت الكود فقط. استخدم حالة `implemented_not_run`.

## 3. البيئة المحلية النهائية
بعد CODE-READY انتقل إلى PH-12 المستقلة. أنشئ Docker محلياً بأسماء volumes ومشروع تحمل `nirab-v2-local`، واستخدم بيانات صناعية فقط وMySQL متوافقاً مع Spatial وREAD COMMITTED. افصل البريد وSMS وFCM والخرائط والدفع وOdoo والتتبع التسويقي بمزودات fake/local، وامنع اتصالات الإنتاج من الويب والتطبيقات والعمال.
لا يجوز اعتبار SQLite بديلاً لقبول اختبارات GIS/التزامن. لا تستعمل dump إنتاج حقيقياً من أجل سهولة الاختبار. أصلح bootstrap المحلي إذا كشف الاسترجاع النظيف تعارضات migrations قديمة دون إعادة كتابة تاريخ migrations المنشورة بطريقة تكسر VPS.

## 4. منع النشر والآثار الخارجية
لا SSH ولا Dokploy API ولا VPS ولا دفع/رسائل/حجز خارجي حقيقي. لا `git push` إلى فرع ينشر تلقائياً، ولا merge إلى main؛ Dokploy قد ينشر بمجرد push. العمل على فرع منفصل `feat/nirab-commerce-v2`؛ مشاركة commit محلي/patch/ZIP تكفي ما لم يصدر إذن مستقل بنشر فرع غير مربوط بالإنتاج.
لا تضف migrations أو reset أو seed إلى entrypoint أو Composer scripts أو pipeline يعمل تلقائياً. أوامر التصفير محفوظة لدليل المالك وتظل fail-closed.
لا تستخدم رموز الوصول الموجودة في ملفات تتبع Clean Life ولا تنسخها إلى كود أو fixtures. لا تجلب أي endpoint من الموقع المرجعي أثناء هذا التنفيذ.

## 5. الانحرافات والقرارات
الأولوية: تعليمات المالك الأخيرة > القرارات الملزمة بهذه الحزمة > العقود والمواصفات > المراحل > اقتراحات المحادثة القديمة. الفروق بين المستودع والأرشيف تسجل في `SOURCE-DELTA.md` قبل التعديل. القرار المعماري المقترح إذا تطلب تعديلاً داخلياً يوثق في `DEVIATIONS.md` مع أثره واختباراته، دون تخفيض المتطلبات. لا تعطل الحراس الأمنية أو التحقق الجغرافي لتنجح الاختبارات.
ما يحتاج قراراً تجارياً نهائياً مثل الأسعار والضرائب المعتمدة والحدود الزمنية يملك إعداداً واضحاً؛ إعدادات الإنتاج تبقى محفوظة، والقيم الجديدة غير المعتمدة تبقى مسودة غير قابلة للبيع. هذه ليست ثغرة لترك ميزة غير منفذة.

## 6. التسليم المطلوب
- commits محلية منظمة لكل مرحلة، وقائمة الملفات المعدلة في كل مشروع.
- migrations جديدة وأمر inventory/reset آمن وseeders مصنفة local/reference وOwner runbook.
- OpenAPI نهائي مطابق للتنفيذ وعقود أخطاء وأحداث، وتحديث الحزمة عند أي تعديل موثق.
- نتائج اختبارات محلية فعلية وروابط ملفات logs/screenshots منزوع منها البيانات الحساسة، مع الفاشل والمعلق صراحة.
- Android debug builds للتطبيقات الثلاثة في PH-12 إن توفرت أدواتها، واختبار على جهاز/محاكي متاح؛ عدم توفر جهاز يسجل كقبول يدوي معلق وليس نجاحاً.
- تقرير iOS منفصل: لا تدّعِ build أو اختبار iOS خارج macOS/Xcode؛ عميل Customer وأرشيف Provider لا يتضمنان مجلد iOS في اللقطة الحالية.
- تقرير آخر يعلن `LOCAL_VALIDATED` أو `LOCAL_BLOCKED`، ولا يعلن `PRODUCTION_READY` أو ينفذ VPS.
- قائمة يدوية للمالك وتقرير فجوات قابل للإغلاق؛ صفر TODO وهمية في مسارات الشراء والمال والجدولة.

ابدأ من PH-00، ونفذ حتى نهاية PH-12 ضمن الحدود المذكورة. لا تمس VPS أو بيانات الإنتاج حتى لو كان أمر التصفير قد نجح محلياً.
