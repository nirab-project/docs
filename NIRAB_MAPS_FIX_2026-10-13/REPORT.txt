الإصلاح الأمني
ProtectPersonalData لا يزال يعمل على استجابات API وتبقى قواعد locations.read وcontacts.read وقواعد الملكية وإسناد الحجز وحجب الأسرار قائمة.
السماح الجديد يطابق GET + المسار الدقيق + اسم Controller/action الفعلي + مسار الحقل داخل JSON.
لا توجد علامة أو قيمة يرسلها العميل لتفعيل السماح، ولا يُورَّث السماح من كائن عام إلى كائناته الفرعية.

المواضع العامة المسموحة:
- customer/config/place-api-details، وكذلك مسار serviceman المقابل:
  content.location.latitude/longitude
  content.viewport.low.latitude/longitude
  content.viewport.high.latitude/longitude
- customer/config/geocode-api، وكذلك مسار serviceman المقابل:
  content.results[i].geometry.location.lat/lng
  content.results[i].geometry.viewport.northeast/southwest.lat/lng
  content.results[i].geometry.bounds.northeast/southwest.lat/lng
- customer/config: content.default_location.latitude/longitude
- provider/config وserviceman/config: content.default_location.default.latitude/longitude
- customer/config/get-zone-id: content.zone.formatted_coordinates[i].latitude/longitude
- zones: content.data[i].formatted_coordinates[j].latitude/longitude

الكائنات الخاصة المضافة إلى نفس الاستجابة، وإحداثيات العملاء والحجوزات غير المصرح بها، وأرقام التواصل والأسرار، تظل محجوبة.

إصلاح Backend
- Google HTTP errors وأجسام error وفشل الاتصال واستجابة Details التي لا تحمل إحداثيات صحيحة تُعاد HTTP 502 مع content=null ورسالة عامة، دون تمرير تفاصيل الخطأ أو بيانات الاعتماد.
- Geocoding status مثل REQUEST_DENIED وOVER_QUERY_LIMIT وZERO_RESULTS لا يُعاد كنجاح.
- Autocomplete الفارغ يُقبل كبحث بلا نتائج، وليس كفشل نقل.
- Field Masks:
  Autocomplete: suggestions.placePrediction.placeId,suggestions.placePrediction.text,suggestions.placePrediction.types
  Details: id,location,viewport,formattedAddress,addressComponents,displayName,types
  Route Matrix: originIndex,destinationIndex,status,condition,distanceMeters,duration
- Geocoding Legacy لا يدعم Field Masks؛ تُفحص حالة الاستجابة ونتائجها بدلاً من إضافة رأس غير مدعوم.
- تصحيح origins/destinations في Route Matrix لتكون قوائم كما يتطلب API، مع إحداثيات رقمية والتحقق من حالة عنصر المسار.
- إزالة قيم بنغلاديش الاحتياطية من Config ومن إعداد موقع النشاط التجاري.
- تصحيح ترتيب GeoJSON من [longitude, latitude] إلى حقول latitude/longitude، وإضافة formatted_coordinates لقائمة المناطق العامة.

إصلاح user-app-web
- رفض الإحداثيات المفقودة وغير المحدودة والخارجة عن المدى و(0,0).
- فشل تحديد المكان لا يستبدل الموقع والعنوان السابقين ولا يرسل حركة كاميرا بديلة إلى (0,0).
- استيعاب addressComponents وlongText وshortText وviewport.low/high في Places API (New)، مع توافق مكونات العنوان القديمة.
- البحث يدعم «الرياض» وRiyadh، ويُشفِّر معاملات البحث والمعرّف، ويزيل النتائج القديمة عند البحث الفارغ أو الفشل.
- فتح SearchAnchor عند الضغط على البحث؛ النتائج الفارغة عناصر غير قابلة للنقر.
- انتظار نتيجة setLocation قبل إغلاق البحث ومنع تكرار الضغط أثناء الطلب.
- تحريك كاميرا المدينة إلى موقع Google الصحيح؛ تحريكها لاحقًا إلى نقطة مختلفة يعيد تحديد عنوان نقطة الخدمة والتحقق من منطقتها.
- مركز النشاط أو المنطقة العامة، والرياض عند غياب كليهما، مراكز عرض فقط ولا تُنشئ عنوان العميل تلقائيًا.
- حراسة تهيئة خريطة المنطقة وشاشة إضافة العنوان لمنع اعتماد مركز العرض كعنوان.
- تحديث مسار البحث داخل نموذج إضافة العنوان إلى بيانات العنوان الصحيحة، بدل الاعتماد على توقيت camera-idle لنقل البيانات.
- التعامل مع فشل الموقع الحالي في المستدعين ومنع حفظ عنوان ذي إحداثيات غير صالحة.
- إبقاء التصفح العام خارج التغطية وفق السياسة الحالية، مع اشتراط التغطية لاختيار عنوان خدمة داخل نموذج العنوان، والتحقق من المنطقة المطلوبة في Checkout.

- إعادة تحديد عنوان نقطة الخدمة بعد تحريك الخريطة والتحقق من منطقة هذه النقطة.
