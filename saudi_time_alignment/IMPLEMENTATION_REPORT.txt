تنفيذ مواءمة توقيت السعودية — 2026-10-24

تم تنفيذ تعديلات المصدر في Laravel وتطبيق العميل/الويب وتطبيق المزود وتطبيق الفني.
القرار: NIRAB_BUSINESS_TIMEZONE=Asia/Riyadh للمواعيد والعمل، مع إبقاء app.timezone=UTC
للطوابع التقنية والطوابير والدفع وتواريخ الإنشاء والانتهاء. لا حاجة إلى تغيير توقيت
نظام التشغيل أو MySQL، ولا توجد migration أو معالجة جماعية للحجوزات.

العقد المنفذ
- النص القديم service_schedule يمثل ساعة عمل سعودية كما هي في SQL؛ 11:00 تبقى 11:00.
- service_schedule_at يحمل ISO 8601 مع +03:00، وحقل timezone يحمل Asia/Riyadh.
- المدخل الصريح 08:00Z يمثل نفس لحظة 11:00+03:00؛ المدخل القديم 11:00 بدون منطقة
  يمثل 11:00 السعودية. قيم starts_at المختارة تبقى كما أعادتها واجهة API عند الإرسال.
- created_at/updated_at/expiry/renewal والأحداث التقنية تبقى لحظات UTC، وتعرض سعودياً.
- ساعات المناوبات تظل أوقات يوم سعودية؛ الإجازات فترات لحظية مخزنة UTC وتقارن بحدود UTC.
- الفترات اليومية للتقارير تفرق بين أعمدة المواعيد السعودية وأعمدة الأحداث UTC.
- مفاتيح تذكير/تغيير الموعد القديمة تحتفظ باشتقاقها السابق لتجنب تكرار الإشعارات.
- لا تغييرات على المبالغ أو محاسبة Odoo أو مفاتيح حجز الزيارة/الدفع.

المسارات المغطاة
- الحجز العادي ومعاينته وتوزيع الفروع والتكرار وزيارات الباقات ومعاينتها وفواصل الزيارات.
- تعديل الموعد من الإدارة/الفرع، جداول الفروع، الطاقات، الفرق، تعارض الفنيين والتذكيرات.
- مدد طلبات التسعير ومواعيد المعاينة، نطاقات تقارير الفرع، قوائم المواعيد وفواتيرها.
- منتقي مواعيد العميل والملخص والتفاصيل والويب والتكرار وانتهاء الباقات واشتراك Pro.
- قوائم وتفاصيل وتعديل وتقويم المزود، ومواعيد وتفاصيل وتعديل وسجل أحداث الفني.
- استخدام قاعدة IANA في التطبيقات الثلاثة عبر timezone 0.11.1 الموجود سابقاً بشكل انتقالي؛
  أصبح اعتماداً مباشراً دون ترقية إصدارات بقية الحزم. تم حل الاعتماد من الذاكرة المحلية offline.

التحقق
النتائج النهائية والأوامر محفوظة في verification.json وملفات final_* بجانب هذا التقرير.
تم استخدام php -l، اختبارات PHPUnit محددة دون إقلاع Laravel أو اتصال خارجي، dart format،
فحوص Dart مباشرة دون Flutter binding، وتحليل Flutter محصور في الملفات المعدلة.
لم يتم بناء التطبيقات أو تشغيل واجهاتها أو تشغيل خادم/حاويات/بيئة كاملة أو اختبارات واجهات.
لا تمثل هذه الفحوص قبولاً تشغيلياً للأسطح الأربعة؛ التحقق التشغيلي مؤجل بحسب طلب المستخدم.

الحجوزات التاريخية — غير معدلة وغير متحقق منها على الخادم

100007: القيمة المرجعية 2026-10-25 12:00:00؛ تحتاج تسوية منفردة مع الاختيار الأصلي.
100008: القيمة المرجعية 2026-10-26 11:00:00؛ لا تُعامل تلقائياً كـ UTC ولا تُزاح.
100009: القيمة المرجعية 2026-11-03 11:00:00؛ لا تُعامل تلقائياً كـ UTC ولا تُزاح.
هذه القيم من وثيقة الخطة فقط وليست نتيجة SELECT نفذه الوكيل.
لم يتم الوصول لقاعدة الإنتاج أو تشغيل baseline ضمن هذه المهمة.
tools/saudi-time-baseline.php أداة SELECT فقط يشغلها المستخدم على الخادم عند الحاجة:
  php tools/saudi-time-baseline.php > saudi-time-baseline.json
تجمع إعدادات جلسة MySQL والقيم الخام وسجل مواعيد محدود وحقول زمنية من التدقيق.
مصدر الاختيار الأصلي قد لا يكون محفوظاً؛ عند غيابه تبقى التسوية معلقة ولا يُفترض فرق +3.
تحتاج أيضاً الإجازات القديمة ومواعيد المعاينة/نوافذ التسعير المدخلة سابقاً بلا منطقة
إلى مراجعة المصدر عند وجود بيانات تاريخية؛ لا يتضمن هذا التغيير ترحيلاً لها.

التجميد والنشر والرجوع — ينفذها المستخدم، لم ينفذها الوكيل
1. خذ نسخة احتياطية لقاعدة البيانات والمصادر وإعدادات النشر قبل تطبيق النسخة الجديدة.
2. أوقف مؤقتاً إنشاء/تعديل المواعيد وحجز/تجديد الزيارات أثناء نافذة النشر وتسوية الحجوزات
   الغامضة. لا تلغِ حجز زيارة أو مفتاح idempotency لمجرد اختلاف تفسير التوقيت.
3. انشر الخادم والعميل/الويب والمزود والفني معاً؛ اترك app.timezone=UTC واضبط فقط
   NIRAB_BUSINESS_TIMEZONE=Asia/Riyadh. حدّث config cache وأعد تشغيل العامل/المجدول على نفس الإصدار.
4. تحقق يدوياً من 26 أكتوبر 11:00 عبر العميل والإدارة والمزود والفني وأجهزة UTC/London/New York،
   ومن حد 23:30، والتعارض بين الحجز العادي والباقات، وتغيير الموعد من الفرع.
5. تحقق من فاصل أسبوعي: 26 أكتوبر ثم 28 أكتوبر مرفوض، و3 نوفمبر مقبول مع بقية شروط السعة؛
   وفاصل شهري: 27 أكتوبر إلى 26 نوفمبر 11:00 = 30*24 ساعة، و25 نوفمبر مرفوض.
6. راجع سجلات الإنشاء والانتهاء والدفع كتسلسل UTC وعرض سعودي؛ لا تطبق أي UPDATE جماعي.
7. عند الرجوع جمّد الكتابة ثانية وأعد النسخ المتوافقة للأسطح الأربعة معاً، وأعد إعدادات
   الإصدار السابق وكاش الإعدادات والعامل/المجدول. لا تُزح بيانات SQL للرجوع. راجع منفرداً
   الحجوزات التي أُنشئت بين النشر والرجوع، خصوصاً إن عاد مسار الفرع القديم إلى تحويل UTC.
8. قبل الرجوع المحلي، راجع changed_files.json والنسخ في before/؛ لا تستبدل أي تعديل لاحق
   للمستخدم بصورة عمياء. ملفات patches/ تحتوي فروق كل مشروع دون تغيير تاريخ Git.
