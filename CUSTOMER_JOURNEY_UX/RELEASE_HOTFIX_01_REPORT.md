# إصلاح مسارات الطلب القديمة وتجهيز تسليم الإصدار

التاريخ: 7 أكتوبر 2026. الحزمة: `RELEASE-HOTFIX-01`.

أُغلقت كتابتا الطلب القديمة في وضع الفروع، وعولجت ملكية الطلب والعنوان عند استعمال الوضع الآخر. أُضيفت بوابة بدء تمنع استعمال حالة وحدات ناقصة أو معطلة. الإغلاق هنا مصدري؛ تفعيل حالة البيئة المعتمدة وجرد Pending الحي والترحيل والاختبار اليدوي تبقى خطوات النشر اللاحقة.

## الإصلاحات

| النتيجة | التعديل | الحالة |
|---|---|---|
| R1 | `PostController::updateInfo` يعيد HTTP 410 في Branch Mode قبل التحقق من المدخلات أو كتابة أي سجل. في الوضع الآخر يشترط customer ويقفل طلبًا مملوكًا داخل transaction، ويتحقق من ملكية العنوان ومنطقة الطلب. يرفض الطلب المحجوز أو ذي عرض أو سياق رحلة الفروع بـ409 | مغلق في المصدر؛ قبول يدوي لم ينفذ |
| R2 | `PostController::store` يعيد HTTP 410 في Branch Mode قبل إنشاء العنوان أو الطلب أو الإشعار. أزيل من الدالة فرع الإنشاء الذي كان يكرر اختيار الفرع بشروط أضعف. في الوضع الآخر يرفض نوع المستخدم غير customer والعنوان غير المملوك | مغلق في المصدر؛ قبول يدوي لم ينفذ |
| توافق العميل القديم | مغلف الرد يحفظ `response_code/message/content/errors`، مع رسالة عربية وإنجليزية تطلب تحديث التطبيق واستخدام شاشة طلب عرض السعر. `response_code=legacy_post_write_disabled` و`content.replacement_endpoint=/api/v1/customer/quote-requests` | يتوافق مع عرض `message` في العميل الحالي؛ الأجهزة القديمة تحتاج قبولًا يدويًا |
| R3 | `docker/start.sh` يفحص حالة `/var/www/state/modules_statuses.json` قبل أي أمر Laravel. لا ينسخ القالب المعطل ولا `{}` عند غياب الحالة. يحتفظ بالحالة المعتمدة ويصلها بمسار FileActivator الحالي؛ الملف الغائب أو غير الصالح أو الذي يعطل وحدة أساسية يوقف البدء برمز 78 | بوابة المصدر مكتملة؛ مقارنة حالة الخادم وتجهيزها لم ينفذا |
| R4 | جرد مصدر 253 ملف migration مع SHA-256، وقائمة إجراءات النشر للمقارنة بسجل البيئة الفعلي | الجرد مكتمل؛ Applied/Pending الحيان غير متحققين |

التعديل في الوضع الآخر يرفض أيضًا الطلب ذا `location_snapshot` أو `branch_id` أو نافذة موعد أو حالة غير submitted، حتى عند إطفاء Branch Mode بعد إنشاء الطلب. أي عرض سابق يمنع تعديل السياق، بما فيه العرض المرفوض أو المنتهي؛ يلزم طلب جديد. لا يُبدّل عنوان لقطة محفوظة منفردًا، ولا يُعدّل طلب محوّل إلى حجز.

لم تُغيّر ملفات routes أو `PostController::show` أو مسارات قبول ورفض العرض. `GET customer/post/details/{id}` يبقى مقيدًا بالمالك، وتستمر مسارات `quote-requests` وقبول العرض عبر `post/bid/update-status`. تتبع المصدر الحالي لم يجد استعمالًا لدالتي `updatePostInformation` القديمتين من واجهات العميل؛ إنشاء quote الحالي يستعمل `quote-requests`، ويُرسل موعد التنفيذ إلى عملية القبول.

## سياسة حالة الوحدات

`modules_statuses.json` المتتبع قالب غير صالح لإصدار نيراب المركّب؛ لم يُعدّل أو يُنسخ فوق حالة تشغيل. يُستعمل الملف الفعلي المعتمد من البيئة الصحيحة، بعد مقارنته بمكونات الإصدار. لا Installer أو Updater أو تفعيل شامل أو تجاوز تراخيص.

الفاحص المستقل `docker/verify-module-statuses.php` يطلب قيمة boolean `true` للوحدات التشغيلية: Auth، UserManagement، ZoneManagement، CategoryManagement، ServiceManagement، ProviderManagement، PaymentModule، BusinessSettingsModule، BookingModule، TransactionModule، CartModule، AdminModule، CustomerModule، ServicemanModule، BidModule، OdooIntegration. الأخيرة تسجل دليل المالية وOutbox والمهاجرات؛ تفعيل وحدة التسجيل لا يغيّر `ODOO_ENABLED` أو مفاتيح الاتصال ولا يستدعي Odoo في هذا الفاحص. تبقى حالة بقية الوحدات والإضافات كما اعتمدها المشغّل.

يُطبّق الفحص تلقائيًا عند بدء الحاوية، ويمكن تشغيله منفردًا على الملف المعتمد للنشر خارج Docker. لا يقلع Laravel، ولا يحتاج Composer، ولا يقرأ قاعدة البيانات أو يعدّل الملف. نجاحه لا يثبت ظهور routes أو migrations فعليًا؛ تُراجع القوائم أثناء النشر. أضيفت قاعدة Git لحفظ `docker/*.sh` بنهايات LF.

## التحقق المحدود

| الفحص | النتيجة |
|---|---|
| `php -l` | نجاح أربعة ملفات: Controller، ترجمتا journey، والفاحص المستقل؛ PHP 8.4.24 |
| `bash -n docker/start.sh` | نجاح فحص الصياغة فقط؛ لم يُنفذ start.sh |
| الفاحص المستقل | رفض القالب المعطل والملف الغائب وJSON غير الصالح وقيمة string بدل boolean برمز 78؛ قبول ملف مؤقت ذو وحدات تشغيلية صحيحة مع AI وAddonModule وGateways معطلة. حُذفت الملفات المؤقتة |
| الفرق والمسارات | مراجعة الفرق؛ لا تعديل routes أو migrations أو ملفات Dart؛ `git diff --check` ناجح |
| الترجمات والترميز | أسماء مفاتيح journey متطابقة في العربية والإنجليزية؛ الملفات المعدلة UTF-8 سليمة |

لم تُشغّل البيئة أو Laravel أو Docker أو build أو migrations أو Unit/Integration/E2E أو اختبارات ثقيلة. لم يحدث اتصال بقاعدة البيانات أو دفع أو إرسال إشعارات أو نشر أو push. لا تغيير للاعتماديات أو الأسرار أو MySQL 8 وSpatial، ولا migration إضافية أو إعادة تنفيذ مراحل UX الست.
