# تسليم نشر نيراب واختباره يدويًا

التاريخ: 7 أكتوبر 2026. ترتبط القائمة بإصلاح `RELEASE-HOTFIX-01`. كل بند تشغيلي أدناه حالته **لم ينفذ**؛ الأوامر مرجع للمشغّل لاحقًا ولم تُشغّل أثناء الإصلاح. تسجل النتيجة Pass أو Fail أو Blocked مع دليل من إصدار الاختبار الفعلي.

## حالة الوحدات قبل بدء الإصدار

1. احفظ نسخة من حالة الوحدات الفعلية في البيئة الصحيحة، وقارنها بالنسخة المعتمدة للإصدار. القالب المتتبع `modules_statuses.json` معطل ولا يصلح بديلاً عن الحالة الحية.
2. جهّز الملف المعتمد داخل وحدة التخزين الدائمة في `/var/www/state/modules_statuses.json` قبل بدء حاويات web أو queue أو scheduler. الحاوية الجديدة ترفض البدء عند غيابه أو تعطيل وحدة تشغيلية أساسية. لا تنسخ القالب، ولا تشغّل Installer أو Updater، ولا تمكّن إضافات غير مستعملة.
3. في نشر خارج Docker، احفظ الحالة الحالية بدل الكتابة فوقها عند نسخ المصدر، وشغّل الفاحص المستقل على الملف الذي سيقرأه FileActivator:

```bash
php docker/verify-module-statuses.php /path/to/approved/modules_statuses.json
```

4. بعد تهيئة الإصدار داخل نطاق وصول مقيد، راجع `module:list` وroutes واكتشاف migrations من التطبيق نفسه. تأكد من وصول FileActivator إلى الملف المعتمد، ومن تحديث حالته المخزنة مؤقتًا وفق سياسة البيئة؛ نجاح JSON وحده لا يكفي. راجع كذلك أي إضافة اختيارية تنوي تفعيلها وفق اعتمادها وترخيصها.

## جرد واعتماد الترحيل

احفظ نسخة احتياطية وتحقق من قابلية استعادتها، وأوقف كتابة الحجوزات عند ترحيل أرقامها. استخرج قائمة الحالة من النسخة الصحيحة والاتصال الصحيح بعد ضبط الوحدات:

```bash
php artisan module:list
php artisan migrate:status
```

قارن القائمة مع [جرد المصدر](RELEASE_MIGRATION_INVENTORY.json)، وراجع كل Pending المكتشف، بما فيه مهاجرات المواعيد والمالية والباقات ونسخ التأكيد وأرقام الحجوزات. الجرد يشمل مصدر الوحدات الاختيارية أيضًا، ولا يعني وجوب تفعيلها أو تطبيق مهاجراتها.

تحقق قبل اعتماد الدفعة من تكرار أرقام الحجوزات:

```sql
SELECT readable_id, COUNT(*) AS total
FROM bookings
WHERE readable_id IS NOT NULL
GROUP BY readable_id
HAVING COUNT(*) > 1;
```

إذا وجدت تكرارًا، توقّف وراجع المراجع التاريخية؛ لا تعِد ترقيمها تلقائيًا. تحقق أيضًا من الجداول الأصلية `users/bookings/customer_visit_packages/services`، وأنواع UUID ومحرك الجداول وcharset/collation. وجود `gallery_images` بلا سجل migration مقابل يستلزم مصالحة schema مع سجل الترحيل.

المهاجرتان الإضافيتان لرحلة UX هما:

- `2026_10_07_000001_create_visit_booking_requests`: جدول مفاتيح إعادة الحجز، بعد الجداول الأصلية.
- `2026_10_07_000002_add_service_gallery_images`: عمود JSON يقبل null في services.

بعد اعتماد **كل** القائمة المعلقة، تطبقها مهمة نشر واحدة، دون تنفيذ تلقائي من كل replica:

```bash
php artisan migrate --force
```

لا تستخدم `--path` لإخفاء مهاجرات سابقة أو تجاوز تعطيل الوحدات. لا تستعمل rollback أو fresh أو reset أو refresh كحل عام؛ بعض down ترفض الرجوع، وأخرى تحذف دليل إعادة الطلب أو بيانات المعرض.

## التحقق بعد الترحيل

```bash
php artisan migrate:status
php artisan route:list --path=api/v1/customer/visit-packages
php artisan route:list --path=api/v1/customer/quote-requests
php artisan route:list --path=api/v1/customer/post
php artisan schedule:list
```

```sql
SHOW CREATE TABLE customer_visit_booking_requests;
SHOW INDEX FROM customer_visit_booking_requests;
SHOW COLUMNS FROM services LIKE 'gallery_images';
```

راجع سجل batch، والقيدين الفريدين والمفاتيح الخارجية لجدول إعادة الحجز، وعمود gallery_images. ظهور المسار القديم في route:list متوقع: الرد 410 يفرضه Controller على عمليتي الكتابة فقط في Branch Mode. لا تحظر مجموعة post أو تعطّل bidding_status لإغلاقهما.

راجع البناء الحقيقي للتطبيقات المتوافقة والعمال والمجدول داخل البيئة المعتمدة. لا تشغّل `schedule:run` كفحص قراءة لأنه ينفذ أعمالًا. راجع تفسير تخزين المواعيد بـUTC وعرضها بتوقيت الرياض؛ لا تغير timezone لقاعدة قائمة بلا مصالحة.

## القبول اليدوي

استعمل حسابي عميل A وB، ومدير فرع وفنيًا مخولين من فريق المشروع، وخدمات وعناوين ومبالغ اختبار. كل صف **لم ينفذ** عند تسليم الإصلاح.

## سجل قرار الفتح

سجل commit وصورة Backend وإصدارات التطبيقات، وحالة الوحدات المعتمدة، واتصال قاعدة البيانات وإصدار MySQL، ودليل backup والاستعادة، وقائمة Pending المعتمدة، وbatch الترحيل، ونتائج القبول اليدوي ومسؤول القرار. يبقى الفتح العام معلقًا عند فشل ملكية أو تكرار خصم/حجز أو سعة أو توقيت أو بوابة دفع مفعلة، أو اختلاف schema عن السجل. لا تعني فحوص الصياغة نجاح التشغيل.
