# مهمة تنفيذ إصلاحات NIRAB للسلة والحجز — لوكيل Codex

تعمل على نسختي Backend و`user-app-web` الحاليتين على جهازي. افحص التقرير `NIRAB_CART_BOOKING_SOURCE_AUDIT_2026-10-12.md` والحزمة المرفقة، ثم طبق الإصلاحات **بالمقارنة مع HEAD المحلي الحالي**، وليس باستبدال الملفات دون تحقق.

**المهمة:** معالجة أخطاء إضافة خدمة للسلة للزائر، حماية هوية السلة، قراءة الكوبونات المعطلة، تحقق عنوان الحجز والخدمات بمقر الفرع، اختيار الفرع والمنطقة، تعديل الكمية والحذف، تحضير جلسة الزائر، منع عرض كاش سلة حساب آخر، دعم نوع الحجز المتكرر و`dates` ودفعه وفق وسيلة العميل، وCallback الويب، مع الحفاظ على تدفقات الحجز والأسعار والصلاحيات الحالية.

1. قبل التطبيق: `git status --short`, `git log -1 --oneline` واحفظ نقطة استعادة. تحقق أن المصدر المحلي يطابق أو يستوعب تعديل ZIP؛ لا تُسقط تعديلات لاحقة أجريتها بنفسي.
2. في Backend طبّق `NIRAB_CART_BOOKING_BACKEND_FIXES_2026-10-12.patch` بعد `git apply --check`. في `user-app-web` طبّق `NIRAB_CART_BOOKING_CUSTOMER_FIXES_2026-10-12.patch` بعد الفحص. إذا حدث conflict، نفذ port يدويًا مع الاحتفاظ بأحدث منطق أعمال.
3. راجع `git diff` كاملًا، خصوصًا مسارات إسناد الفروع والمدفوعات وتجديد الضيف، ولا تُغيّر MySQL schema أو Modules أو صلاحيات الإدارة دون حاجة مثبتة.
4. نفّذ فحوصًا خفيفة: `php -l` على الملفات الثلاثة المعدلة، `php artisan route:list --path=api/v1/customer/cart` إذا كان Laravel متاحًا محليًا، و`flutter analyze` على ملفات Dart المتغيرة و`flutter build web` إن كانت التبعيات متاحة. اختبارات PHP المعزولة وعقود المصدر ضمن `NIRAB_CART_BOOKING_REGRESSION_TESTS_2026-10-12.zip`؛ هذه ليست بديلًا عن اختبارات Laravel.
5. إن توافرت بيئة MySQL 8 اختبارية معزولة نفّذ Feature Tests فعلية للسلة والحجز والـSnapshots وWallet ورفض `guest_id` المزيف؛ لا تنفذ أي اختبارات مدفوعات حقيقية أو رسائل SMS فعلية.
6. جهز قائمة Smoke Test بسيطة على Web وهاتف Android حقيقي موصول بالكمبيوتر، لا محاكي. الاختبارات اليدوية البصرية يقوم بها المالك وفق تقرير التدقيق. لا حاجة لاختبارات ثقيلة على جميع أجزاء المشروع.
7. سلّم **Commits محلية مستقلة** للإصلاحات Backend وCustomer، مع تقرير واضح: الملفات المتغيرة، نتيجة فحوص التنفيذ، التعارضات إن وجدت، وما لم يتم التحقق منه تشغيليًا. **لا تعمل Push/Deploy/Migrate أو تحذف/تعدّل بيانات الإنتاج دون موافقة المالك.**

**شرط إغلاق حاسم:** يجب التأكد من استثناء Laravel الحقيقي لخدمة `POST /api/v1/customer/cart/add` على Dokploy. إذا كان 500 صادرًا عن SQL أو migration أو Module غير متوافق، قد تحتاج متابعة مستقلة لا يغطيها Patch الحالي؛ لا تدّع علاج الإنتاج قبل Smoke Test.
